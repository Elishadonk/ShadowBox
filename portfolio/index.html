02 — Flagship Project

SHADOWBOX

RoleFounder & Developer
Timeline2025 — Present
StatusActive Development

ShadowBox is a privacy-focused communication platform built around reliable, real-time messaging and calling over local network infrastructure. The project is local-first by design: rather than depending entirely on centralized internet infrastructure, ShadowBox is engineered so devices on the same local network can communicate directly and reliably. It is not a replacement for the internet — it's a deliberately-scoped, local communication system, built and tested end-to-end by one developer.

System Architecture

ShadowBox is built as a layered system — from the application UI down through real-time communication services to the network transport that carries every message, call, and file between devices.

What I Built

  • Real-time text messaging
  • Image messages and voice notes
  • Voice and video calling
  • Permanent user identity and contact management
  • Local SQLite storage for messages and app data
  • Android services and native components, where required by the platform
  • Local network communication between devices on the same network
  • Physical-device testing across real hardware
  • Connectivity troubleshooting and debugging

Engineering & Tooling

The backend is built on Node.js and JavaScript, with LiveKit handling real-time voice and video transport. The client stores messages and identity data locally in SQLite, so the app remains usable and consistent without depending on a remote database for every read. Development runs across Linux environments, with Git and GitHub for version control throughout.

On the networking side, getting real-time communication working reliably over local infrastructure meant working directly with TCP/IP and UDP, testing behavior over Wi-Fi and LAN, and verifying connectivity between peer devices by hand. I used Wireshark to inspect traffic during development and ADB to test and debug the Android client directly on physical devices.
